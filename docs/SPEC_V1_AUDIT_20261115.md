# 《WENGUA 问卦 · UI & UX 设计规范 V1.0》对照现有实现的只读审查

2026-11-15。只读审查：本文件之外没有改动任何代码。依据为仓库代码（`src/`、`apps/mobile/src/`）和 `data/` 中的实际数据。规范第 14 节要求说明五件事，前五节逐一回答；第 6 节按 15 项验收清单列出现状；第 7 节列出规范与现有实现的冲突，这些需要产品方先定。

## 1. 起卦算法及具体规则

**时间起卦（默认方法）**：采用《梅花易数》「年月日时起例」，实现在 `src/index.js` 的 `castByTimeParts`。
- 上卦 = (年支数 + 农历月 + 农历日) ÷ 8 取余。
- 下卦 = (上述之和 + 时支数) ÷ 8 取余。
- 动爻 = 总数 ÷ 6 取余。
- 先天数：乾1 兑2 离3 震4 巽5 坎6 艮7 坤8。

**历法换算**：见 `apps/mobile/src/domain/calendar.ts`，使用 lunar-javascript 1.7.7（MIT 许可，版本已锁定）。每次起卦都把下列规则原样存进卦案：

| 规则 | 默认 | 可选 |
| --- | --- | --- |
| 时钟 | 用户本地时间直接换农历（海外常见做法） | 先换成北京时间 |
| 子时 | 23:00 起算次日 | 晚子时仍算当天 |
| 闰月 | 按本月数 | 按下月数 |
| 年支 | 正月初一换年 | 立春换年 |
| 月建（旺衰用） | 按节气交节时刻精确换月 | — |

时区、夏令时：
- 卦案里存 IANA 时区名（如 America/New_York）、当时的 UTC 偏移和本地钟面时间，已经包含夏令时。
- 起卦时刻由调用方显式传入，引擎内部不推断时区。
- 已知限制：节气表按北京时间排定。北美用户在交节当天前后，月建可能和按当地时间计算的结果差一天以内。这一点已写进每次起卦的 `notes`，但目前界面上没有提示用户。

**其他起卦法**：都在 `domain/methods.ts`，每种方法都注明了出自原书哪一节。
- 物数占（数字起卦）
- 声音占
- 字占
- 丈尺占、尺寸占
- 端法后天（物象加方位）

规范所说的「数字起卦」相当于其中的「物数占」。

## 2. 互卦、变卦、体用与五行

这部分在 `createReading` 中实现。

**变卦**：本卦动爻阴阳互换。

**互卦**：默认取本卦二三四爻为下卦、三四五爻为上卦（`inner-lines`）。另有 `pure-use-changed` 可选。

**体用**：
- 动爻所在的经卦为用，另一经卦为体。
- 同一个体贯穿本卦、互卦、变卦。
- 互卦没有独立的动爻。
- 用九、用六不算第七爻。

**五行生克**：分五类关系，即体生用、用生体、体克用、用克体、比和。以体为中心，逐一列出它与用、互、变的关系。

**旺衰**：
- 用 `assessSeasonalQi` 按实际月建判定旺、相、休、囚、死五态。
- 十二个月令各有独立的键。
- 不使用自创的数值倍率。

**空亡**：引擎能计算，但按产品规则，断语一律不采用空亡。

## 3. 古籍知识库的来源与版本

**原文**：
- 《梅花易数》原文存放在 `sources/original`，规定不得改写；订正另有记录和出处。

## 4. 「模型解释、检索和校验」的实际流程

**不存在模型解释环节。** 应用里没有调用任何 AI 或大模型接口，也不联网。所有资料随安装包一起打包，离线可用。

实际流程如下：
1. 起卦，得到本卦、动爻和月令。
2. 按「问项 + 本卦 + 动爻 + 月令」精确查找已写好的断语（`domain/judgment.ts`）。
3. 按实际起卦日换算应期日期。
4. 把结果整份冻结进卦案（`withJudgment`）。

有几条保证：
- 查不到断语时显示 pending。有草稿但没过审的不显示，也不拿其他问项、其他爻或其他月令的稿子代替。
- 以后断语库更新了，旧卦案也不会被改写，因为保存的是起卦当时给出的版本。
- 校验在构建阶段完成，靠 `npm run validate:*` 系列校验脚本和 `checkInterviewShort` / `checkInterviewDecision` 等拦截检查。

因此，规范第 07 节的「检索古籍 → 整理解读」两段等待、「AI 服务失败重试」、「重新分析」，在本产品中都没有对应的东西。规范要求的「报告可稳定回看」和「不伪造引用」，现有架构已经天然满足。

## 7. 规范与现有实现的冲突（需产品方决定）

1. **AI 解读**：规范默认解读由模型生成、需要检索古籍。现有产品的断语都是事先写好的定稿，不用模型。建议保留定稿制：它更符合「有据」，也更符合「卦案可稳定回看」。规范里与模型相关的状态和文案都应删去。
2. **自由输入问题**：规范第 05 节设计了 500 字的自由提问和改写建议。现有断语是按固定问项撰写的，自由输入的问题没有对应的稿子可答。建议保留目录选题；如需自由填写，只作为私人备注，并明确告诉用户备注不参与解读。
3. **深色仪式与浅色阅读**：规范主张品牌页和起卦仪式用深色（#202724），阅读用浅色。2026-11-14 用户已决定全部改为宣纸，因为深色殿堂「像游戏」。两边的色值几乎一样：象牙白 #F3EEE4 对应现用 #f3eedf，朱砂 #A45145 对应现用 #ac5145。是否让仪式页回到深色，需要用户再定。
4. **品牌名**：规范用「WENGUA 问卦」，现用「三清问道」。
5. **导航命名**：规范是底部「问卦 / 卦藏 / 典籍」，现用顶部「问事 / 问事录 / 藏经阁」，功能可以一一对应，只是名称不同。
6. **拟物元素**：规范建议避免「过度拟真的卷轴」。现有的签筒、竹签是用户亲自提供的画，并要求原样使用，因此保留，除非用户另有决定。
