# Claude 实施任务 · 统一三清问道入殿动画

请直接在当前仓库实施并运行验证。先读取本目录的 [美术规范](ART_DIRECTION.md)、[素材清单](asset-manifest.json) 和三张 `keyframes/`。记录当前 Git SHA 和工作区状态，在独立分支或工作树完成。基线截图保存在 `reference/`。开始前确认当前分支上的文件结构与路径。

## 目标与范围

用户认可 `reference/01-login.png` 里的登录背景。以 `reference/sanqing.webp` 和该截图为最高视觉基准，重做登录之后的「月下殿外 → 推门 → 三清殿落位」三段。延续图一的暖象牙高光、克制的香槟金、带细节的墨棕阴影和柔和光比，让三个镜头有同一栋建筑、同一夜晚的连续感。

保留登录原图、三清原图和座位关系。观者左侧太上老君，中间稍高稍后为元始天尊，右侧灵宝天尊。人物用现有 WebP，优先通过环境光、接触阴影和背景明度让人物融入。沿用六大领域、52 个细分、游客及账号、跳过、简洁问事、起卦状态机、观卦与读卦、付费、历史和断语规则。场景改动的范围止于入殿、殿内初始视点与共用背景材质。完整仪式、简洁入殿、跳过和无 WebGL 路径应落到同一业务状态。保留现有牌匾「三清殿」字样和 Web 无障碍操作。

## 按三个镜头实施

1. **月下殿外**。按 `keyframes/01-moonlit-courtyard.png` 取景，完整读到屋脊、檐口、门及石阶。启用 `runtime/moon-and-mountain-matte.webp` 时，放在院外镜头的远景平面或相机对齐的背景上，取样边缘 Clamp。利用镜头投影固定月亮在上方右侧的构图，保留原有真实灯笼、香炉、柱廊和近景视差。采用同图天空时移除原先独立发光月和叠画的远山，防双月、地平线重影。对向月面的一侧屋瓦和石沿保留冷灰亮边。暖灯照亮地面局部，香烟薄且低。备用开场可读 `runtime/courtyard-fallback.webp`，保留 CSS 可点的操作入口和原有 2D 问事流程。
2. **推门**。按 `keyframes/02-open-threshold.png` 对齐双门位置。现有左右门轴和向内转动保留。用 `runtime/door-leaf-albedo.webp` 配门面 UV，边材取乌红漆木，补低段数倒角、门框收口和旧铜环。铜环挂在两扇门的近中缝侧，门开后跟随门体。贴图中的格子是正交木格纹样，背面、边缘与实体厚度应有一致 UV 和材质。旧程序发光格纹与旧法线位置不对应新图，关闭其发光与法线，待制作 UV 对应的浮雕再使用。通过后方灯笼和门槛反光交接冷暖，保持门楣、同一匾额、门槛和殿内红毯的位置连续。镜头在门扇张开留足视线后通过门槛。
3. **殿内落位**。以 `keyframes/03-hall-lighting.png` 的暗木背景、局部暖光和古铜香炉为准，把实际三尊原图与牌匾加回当前 3D。压低供桌亮黄、花瓶的高饱和蓝、柱体硬高光和云纹密度。保持三人面部高于供桌的视觉亮度，左右法冠与肩部有呼吸空间。香炉在正面中轴以下，烟只停在低处。先停稳镜头，再露出问事托盘。检查小屏、选题后及托盘展开时的脸部留白。

## 素材接入与交互

- 精确引用用到的文件，复制选中的 `runtime/` 到 `apps/mobile/public/art/entrance/`。以 `import.meta.env.BASE_URL` 生成路径，确保 Vite 部署子路径与 Capacitor 壳内本地访问。既有材质依旧是资源失败时的回退。保持贴图缓存、引用复用、卸载/重建时的资源释放。
- `map` 使用 `THREE.SRGBColorSpace`。云纹亮度遮罩用 `NoColorSpace`，白色透出材质颜色。香烟 WebP 自带 alpha，作为 `map` 使用。核对透明图边缘与门纹在移动端 mip 下的效果。
- 以 **约 7.5–8.5 秒**为完整走入的起始目标。示例节奏为 0–2.8 秒缓推，2.8–4.3 秒开门，4.3–7.3 秒通过并向三清落位，最后托盘进入。用户动作与实机表现可决定最终参数。门轴、镜头、UI 显示、音效以同一可见时间进度为准，核对现有独立 wall-clock 完成计时。切后台恢复时确认镜头/门状态一致；跳过后立即完成落位。减少动态可直达殿内或只做短淡变。
- 衔接用同色温的局部照明和渐进落位，保留登录图和画面焦点。保留可点跳过按钮。白闪、重模糊、全屏金雾和高强度 Bloom 会遮掉已认可的细节，应从测试候选中排除。

## 验收交付

1. 在 320×568、375×667、393×852、430×932 的浏览器视口采集同一时刻的远景、门扇半开、殿内落位，与 `reference/` 和 `keyframes/` 并排。标注真实设备或仿真；如有 iPhone，补 Safari 与 Capacitor 真机截图。记录使用的灯、UV、资源路径和实际加载重量。
2. 夜景可见月面与山层，门材质可辨，门按正确方向开合且镜头不穿模。殿内三尊原像在正确位置、脸可辨，操作层和烟不挡脸。「三清殿」文字准确。
3. 跑首访完整入殿、再次进入、连续点击、跳过、减少动态、切后台恢复、关闭 WebGL、缺少新贴图的回退，以及问事、观卦、读卦切换。相机验收包含石桌本互变与安全区回归；避免共用曝光改变卦爻可读性。
4. 在仓库根执行 `npm run app:test` 和 `npm run app:build`，并做实际运行检查。记录启动时间、贴图数量、帧耗时和 draw calls，分别记录殿外／开门／落位。高端机争取 60fps、中端至少流畅 30fps；结论依据实际设备实测。未测项写明设备或环境限制。
5. 提交代码、实际采用的运行素材、来源说明、前后截图与测试结果。大改前先提供三张真实渲染对照，供用户确认镜头与色彩。保持原发布分支独立。
