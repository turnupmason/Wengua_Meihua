# 给 Claude 的开发任务 V6

请在 https://github.com/turnupmason/Wengua_Meihua 中继续开发“问卦 / Wengua”。先读 CLAUDE.md 和 docs/INTERPRETATION_AUDIT_V2.md。V6覆盖旧版关于仅按大领域套稿、旧稿可发布、任意传递生克和已核准精确应期的表述。先检查真实文件再实施，不从零杜撰知识库。

## 产品体验

我要一款由个人维护的手机应用。第一视角进入道观，在高大的三清像前行礼、上三炷香，再看面前石桌逐渐显出本卦、互卦、变卦。沉浸感要足，文字要少、清楚、容易点开。

先实现移动竖屏可运行版本，保留已有知识层与测试。按仓库能力选择轻量3D方案，不为仪式动画先搭复杂后端。场景、镜头、香火、烟雾、磕头与显卦分步实现，每阶段有可运行结果。若用Web实现，说明手机安装与后续封装路径。直接完成可逆开发，不停在技术讨论。

流程：选择领域 → 选择具体事项 → 确认所问 → 仪式 → 石桌显卦 → 点击详解 → 保存这一盘。先明确所问再起卦，不混问。仪式可跳过、可减少动态效果，兼顾设备性能。

石桌三个卦从左到右对应目前、本卦；经过、互卦；结果、变卦。只显示卦名、固定基础等级及必要标记，不一次铺满正文。等级读取原数据，44天风姤为中卦，不能由模型更改。基础卦等与本次情境总断分开。

标出“体：自己；用：所问之事”，画有方向的生克箭头和简短解释。体克用的意思要按所问的门类，不能一律翻成吉。动侧为用、静侧为体；用户曾称“体卦动爻”，实现应按准确规则处理。

真实动爻只在本卦对应位置发光，点击显示本卦该爻的爻辞、小象、白话和出处。互卦没有额外动爻；变卦可标对应变化位置，不能冒充另一次发动。普通爻自下向上1–6，用九/用六另列。

详情能查看本体、本用、体互、用互、变卦承原体、变用六个位置。一个原体贯穿，不是三个人或三份独立体力。关系图的候选路径不能全部画成已经生效的助力。

## 数据真实状态

已有64卦、384普通爻、古籍章节、详细注解、月令基础稿、历法换算和二维演示。原上传文件、修订稿、参考解释与隔离片段分层保存；参阅 docs/EDITORIAL.md、docs/DETAILS_AUDIT.md、data/issues.json。注解不能反向修改六爻结构，未认证解释不能偷偷进入事实表。

客户尾款已生成1,920篇基础稿、16,617个空亡版本。全文由编辑材料和显式规则在构建阶段生成，不是1,920篇分别人工手写。当前九项断法审核通过、可正式发布的数量为0。保留稿件与进度，不把编写数量当作审核完成。

旧编写器的月令、间接作用、部分空亡、结论权衡和应期仍需修订。先修订十篇具体问题样稿、逐项复核，再扩批。古籍案例分清原断和原书记载的反馈，新用户故事不能复制历史结局或补写反馈。

1920来自64本卦×6动爻×5月令气类。互卦、变卦由本卦和动爻确定，不另乘64互卦×64变卦。空亡与具体事项另审，不用无效笛卡尔积制造稿量。

## 问题分支

正式选择读取 data/question-items.json：18个原典门类，每门5项，共90项；75项占问、15项古籍查阅。这些是编辑选出的常见问法，不是搜索数据。界面可另设导航大类，但保留 domainId、question_type、questionId。

question_type 决定解释角度和适用规则，questionId 决定精确稿件。能否开始恋爱、能否复合、能否成婚、婚姻能否安稳分别处理。不能用“婚可成”证明“他喜欢我”，不能声称卦象核实了对方心理。未审核的现代细分标记待补，不以另一问题代答。

求职结合求名及经审核的现代适用规则；自己归程与等人归来不同；手机和钱包可共享失物找回类型，不扩展为失联人员定位。共享类型不自动允许换取另一 questionId 的稿件。未来共享审定内容资源时，显式建立适用映射并验证问题意思和证据一致。

不需要AI识别用户提问。若保留自由填写，只作为备注，写明以所选事项为准；备注里的其他问题不表示软件已经回答，不用关键词偷偷改变类型。

75项各覆盖当前五类月令，有144,000个事项基础匹配槽位，不等于必须创造144,000篇完全不同文章，更不等于现在已完成。同类且审定等价的场景可显式引用共同全文，不能遇缺稿就任意替换。

## 规则与证据

严格采用 docs/INTERPRETATION_AUDIT_V2.md。本用看开局，体互/用互看中间，变用看结局；始终以原体为参照。用最紧、互次之、变又次之；体互比用互更紧。这是判断优先次序，不是数值权重。既不凭单个用克体判永久失败，也不只看变卦倒推情节。解释先吉后凶、先凶后吉和主要反例。

全部经卦使用同一旺相休囚死表。assessSeasonalQi 给完整五态，buildInterpretationEvidence 汇集六位置证据。旧 createReading.strength 保留历史兼容语义，不能混作同一规则。金休仍有克木关系，火死不等于零作用或真空；不自行加能量分数、成功率或倍率。

月令气类不是月支，也不是公历月份。节气切换和四季土边界尚需明确。开发演示可显式选择气类；自动选择月令必须补历法提供者和边界测试，不能直接把11月等同冬水。日历换算按日可不用时分；节气临界和按时辰计算需实际时间。

先看所有用互变对原体的直接关系，再审查间接规则。full-chart.chains 只是两段候选路径；approvedIndirectRules 当前为空。启用前逐条登记来源定位、角色组合、事项、旺衰、动静、空亡条件和优先级。不无限串联、不循环、不重复累计原体或重叠助力，不让间接路径随意推翻直接关系。

旬空另列为用户扩展。八卦配支是后天方位表，不称纳甲或原书通用标准。坤未申仅未空时，只标部分命中，不判整坤空、不推一半钱收不到；部分空亡影响细则未审定。真空需起卦时独立证据，不因五态为死自动成立，后续填冲不自动复活。填优先、冲次之，合空默认不作通用释放依据。

## 应期与日期

先证明此事为什么取这个应期，再换算几号。每个候选说明应什么事件、偏吉偏凶、方法、尺度、来源、适用条件和轮次。婚姻原文的吉凶年月不自动缩成某一天。凶期说清是哪一种所问事件受阻，不扩大成那天万事皆凶；换日也不保证成功。

规则不足不写日期。干支日转换正确不能证明当天收款或复合，不为填满段落而编造“第几天必应”。

手机冻结起卦当地完整 castingDate，按日调用 getCivilDay。近期先找本月剩余合格日期，没有再查下月实际干支；不能把同一日号直接搬到下月。新盘日期>=castingDate，历史盘保留原窗口，跨月阅读显示原年月。按时辰时另排除已过去时段。

findUpcomingCivilDayMatches / formatUpcomingCivilDay 负责日历显示。正文可写本月/下月几号，内部保存完整日期。内置日期表越界时返回缺上下文，不编造映射。取期尚未审核时不调用日期输出填补空缺。

## 稿件审核与接口

用 createQuestionRepository({library}).getContent 精确匹配事项、盘、月令和起卦上下文。可传 question_type 校验一致性，不改变固定事项。

- reference：古籍查阅，可显示来源说明，不作现实预测。
- pending-authoring：精确条件没有稿，显示资料尚未覆盖，不回退别的事项。
- pending-review：有稿但九项未过，story:null、空段落、productionAllowed:false，不显示预测正文和应期。
- review-preview：仅内部 editorialPreview:true；未审稿 productionAllowed:false。旧日期 resolved 只代表日历转换，interpretationReviewed:false，正式产品禁止启用。
- authored-base / ready：精确内容、规则版本及九项批准后才可能返回；ready另须满足日期前提。

data/interpretation-reviews.json 当前没有批准记录。九项包括结构、体用、问题占法、生克、统一旺衰、扩展来源、有限间接作用、可复算应期、结论及反例。批准绑定内容摘要、上下文与政策版本，记录证据定位、理由、审核者与时间。程序验证记录是否齐全，不能替代断法实质审核。

SQL全文以 structural-only 保存为内部稿。生产读取 approved_fixed_question_stories，当前0行；旧导出器拒绝非零批准数。未来须实现精确审核回执导出并测试，不能只改计数或 review_status 放行。

旧 getStory 和通用1920稿只供资料/开发，不绕过具体事项审核作正式结果。也不能因为新接口挡住旧稿，就从基础表、资源字典或另一入口拿来显示。

## 正文与详情

每篇用开局、过程、结局、总断，先说这件事如何推进，再说最终倾向。专业依据放可展开详情：原体、本用、体互、用互、变用的关系与旺衰、空亡、动爻、来源、应期。正文不写成计算日志，不用“帮助没有断”“已有同类接续”等生硬句子。

明确回答所选问题，允许有依据的条件和倾向；证据有反复就说清。不能为“具体”编心理、金额、人物、概率或保证结果。真实动爻解释变化，爻辞的人物、刑罚等不直接移植成用户必遇事件。正文不用星号。

不把旧稿同义替换宣称完成重写。先修订十篇具体事项样稿，覆盖不同生克、旺衰与反向证据；逐项披露已通过项及未定项。
