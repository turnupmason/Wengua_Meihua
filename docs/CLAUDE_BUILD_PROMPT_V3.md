## 月令与应期的两个用途

故事索引 `monthOrder` 仅接受：

- `spring-wood` 春木当令
- `summer-fire` 夏火当令
- `autumn-metal` 秋金当令
- `winter-water` 冬水当令
- `seasonal-earth` 季月土当令

月令用于看五行旺衰，前台叫“月令”。月令与六个经卦的生克均有结构记录；月令生扶或明确日建生/比扶时，`supportEvidence`保存来源，按用户的假空规则处理。不要改回十二个月支故事。应期仍可以使用戌、亥、辰、巳等支作为填冲或卦气候选；这不等于用它们代替月令索引。

原典当前仅明确给出旺、衰的对应，其余五行保留 `not_explicit`，不可自行补造完整旺相休囚死规则。当前预写库按标准 `inner-lines` 互卦，换另一套互卦规则须生成匹配文案版本，不能偷偷混用。

## 故事要怎样出现在产品里

主桌依旧少字：三卦名称、固定等级、体用位置、生克短句、目前→经过→结果。天风姤最终显示“中卦”。

用户点“查看此事走向”，才展开故事。故事像一程事情的展开，把眼前处境、中途转折和末段承接讲清，把时令及空亡影响融进去。使用已有 `result.story`，不把结构调试字段、模板ID、数据库信息塞进正文。

应期作为故事的最后一段，同时提供可展开的依据。给出条件、时间尺度和可观察节点；没有历法转换依据时不造公历年月日。用CalendarProvider处理美国用户的IANA时区、夏令时与换日点，再把相对日数转换成当地日期。

点具体爻仍打开同一原卦、同一1至6爻位的经文、白话和新编经义；浏览其他爻不能改变本次动爻。连续点选用请求序号防止旧请求覆盖新选择，联调页已有实现。

## 案例准确性是硬要求

古籍案例独立放“古籍断案”阅读区，保留原断、原书反馈与原文入口。它们不是新用户未来的结尾。

- 观梅本节未另记后验，显示“本节未另述反馈”，禁止补写成女子次日确已受伤。
- 同是姤四爻动，借斧与老人忧色两案事由、原数与动静不同；禁止仅凭同盘贴同一现实结果或同一数字应期。
- 牛哀鸣的原断是二十一日内，书中反馈是后二十日；两个数字原样区分。
- 少年喜色的贲卦互为上震下坎，对离体有生也有克；禁止把原文泛称改写成全盘都生体。
- 寺额保存添笔前后两盘；字画数按原书所给假设，不能擅改成现代笔画表后仍声称复现原案。
- 实际反馈属于书中记载，不标成项目独立验证的历史事实。新盘的 `reportedOutcome` 始终为空。

故事是前瞻性的传统解读，不是替用户编造一段已经发生的经历。允许象意画面，不制造现实人物、具体地点、伤亡、金额或后验事件。

## 空亡与应期不可回退的规则

起卦时真空优先，未来填冲不自动复活；动不为空、旺不为空，得扶假空与静空分开。相似的“空”不能套同一句结论。

克体来源空，可以减轻该项压力；助益来源空，落实条件需再看。部分命中不把整个经卦清零。固定吉凶等级与这种情境叙述保持独立。

首选填实、次选冲实。合空默认关闭，只有显式启用、婚姻/合作场景、且动或得令/生扶假空成立时才列限定候选。静空仅遇合不能自动出空。

数字应期需要原始起卦输入及现场动静；只给卦号和动爻时，不输出“肯定五天/十七天”。无尺度时保留候选支及取尺度说明，日干支未知时不编相对日数。时干支不能冒充日干支；同盘各角色的干支基准不一致则拒绝。数应出现分数时保留待解释，不自动舍入。

天时按三卦天象与时令合看，不用体克用简单判晴。生产、疾病为传统文献参照，不由卦象输出诊断、药方、停药、生死或具体医疗时点。

## 四、完整用户流程

### 1. 简洁入口

显示应用名“问卦 / Wengua”和“入观 / Enter”。入口可选择语言、声音开关与减少动态效果。用户问题和事项分类可在入观前轻量填写，也可留空。不强迫注册。

### 2. 入观

竖屏第一视角，从道观入口看见内部结构与远处三清像。通过短镜头推进或触摸引导到祖师像前；移动端不要求玩家操纵复杂的游戏摇杆。入口、殿堂、像与石桌要在空间里有明确关系。光线偏暖、低饱和，少量烟与空气尘埃；不做刺眼闪光、镜头抖动。

### 3. 跪拜、上香与磕头

触摸“静心上香”后触发连续动作。镜头降低表示跪下；三炷香应清楚出现、点燃、插入香炉。每炷香有细微火头与烟线。之后完成磕头，镜头运动舒缓。三炷香不是三次重新随机起卦。

提供“跳过仪式/直接观卦”，以及减少动态效果模式。跳过与完整播放必须得到**同一份已经冻结的起卦结果**。音频需要首次手势后再启用；切后台后暂停动画和音频，恢复时不重复起卦。

### 4. 石桌显卦

镜头移到石桌，桌面有可读的空间与留白。按本、互、变顺序显现三组完整六爻，效果是刻痕与柔和金色微光，不是悬浮游戏卡牌。可先做能清楚表达刻痕的几何/材质方案，再逐步加法线、粗糙度和刻字细节。

三组下方始终只放少量信息：

```text
本卦 · 泽火革        互卦 · 天风姤        变卦 · 泽山咸
   上上卦                中卦                中上卦
     目前       →        经过        →        结果
```

示例来自本卦49初爻动；显示等级必须读取当前资料，不照抄演示文字到所有卦上。

**等级最新要求**：44天风姤最终显示“中卦”，之前改上上卦的要求已被用户覆盖。其他卦保持原表。五档分类按 `canonicalGrade`，前台文字用 `rawGrade`。不要自加“上卦”第六档，不把“中卦”又自动改回上上或中上。

### 5. 体用与生克箭头

在本卦对应的上下三爻旁，直接标明：

- `体：自己 · 主`
- `用：事情 · 事`

可以补一个经卦名和五行，如“体 兑金”，但不要同时堆出整套规则解释。箭头必须与真实的生/克方向一致，并配一个关系名与一句短语：

| 关系 | 主界面短语 |
| --- | --- |
| 体克用 | 主制事 · 可掌控 |
| 用克体 | 事克主 · 主不顺 |
| 体生用 | 主生事 · 有耗费 |
| 用生体 | 事生主 · 有助益 |
| 比和 | 主事相和 |

比和使用双向或无方向连接，不能画成单向克。当前 `edges` 保留真实 from/to。箭头既有文字也有形状区分，不只靠红绿颜色。

这句是结构关系提示；领域与月令可能改变实际解释。例如饮食占中“体克用”有“饮食有阻”的专门语义，不能因此仍宣告“本次必吉”。详情优先引用该领域条文。

### 6. 精确的动爻发光

最重要的数据交互：**本卦的哪一爻动，就让那个位置发光，并显示那个位置对应的原文、白话和小象。**

初爻在最底部，上爻在最顶部。对3D模型应保留 `hexagramId, stage, linePosition`，射线命中后以这些字段查询。阴爻有左右两段，但属于同一条爻，触摸任一半段查同一个记录。

动爻所在的三爻经卦为用，另一个静止经卦为体。用户口头提到“体卦的动爻”时，此处按本卦动爻实现，不改变经典体用定义。

默认只有本卦的本次动爻用持续金色微光标记。互卦没有新的独立动爻。变卦可以用另一种低强度标记提示“对应变化位置”，不能伪装成第二次发动。详情浏览其他爻使用“选中态”，与本次动爻视觉区别明确。乾用九、坤用六放特殊条目，不画第七条爻。

在64卦详情库里，用户可以逐爻点击；从本次占卦进入时自动选中本卦真实动爻，不因打开面板改掉起卦结果。

### 7. 点击才展开解释

点卦名/整组卦象打开底部详情面板，点某一爻直接定位到它。详情至少包含：

1. 卦名、用户等级、当前阶段、上下经卦。
2. 卦辞与对应白话。
3. 大象与白话，和用户提供的吉凶诗象明确分开。
4. 当前爻的爻辞、白话、小象与白话。
5. 体用、生克、月令、旬空的本次依据。
6. 适用领域的古籍原文、相关章节与来源入口。

长内容允许收起“古文/白话/断法依据”，阅读时不遮断关闭和返回操作。主桌面不承载这些长段落。

### 8. 保存与重看

起卦时冻结结果并生成 cast ID，保存问题、领域、起卦法、原始数值、完整时间/时区、历法换算结果、规则版本、动爻、三卦 ID 与显示等级快照。文字详情可按 contentVersion 重现；用户规则更新后旧记录应仍能解释当时采用了哪一版，不能后台偷偷换结果。

用户问题和历史默认只在本地。支持删除和导出；不把问题自动发给模型或埋点服务。

## 五、起卦与历法接入

首先提供可靠的手动联调模式：选本卦与动爻，直接验证三卦与资料。正式流程默认采用卷一《年月日时起例》，可增加明确命名的报数方式。不同方法保留不同输入与规则，不能把不明算法都称为古法。

时间法已提供 `castByTimeParts`。调用方需提供年支序数、农历月日、时支序数；不要把公历年月日直接送进公式。美国用户必须记录 IANA 时区，覆盖夏令时开始、结束和本地跨日。

请建立 `CalendarProvider`：输入带时区的明确时刻，输出农历月日、年支、月建、日干支、时支和边界政策。选定可验证的历法实现，记录版本与来源并核对样例。农历起卦月与论旺衰的月建分开。换年、节气月建、闰月和子时换日政策显式存储，不因设备时区变化重算已保存记录。

没有足够依据的历法边界先保留为可配置政策，同时把可靠的手动输入与仪式流程做完整；不能用 `new Date()` 的当前公历月替代月令后宣称已完成。

## 六、月令、全盘生克与空亡

基础等级只来自表。当前三卦在特定事情中的走势，使用领域断法、体用、互变、旺衰与用户空亡规则另行解释。不要先拍一个0–100的能量分数，再反过来写成古籍定论。

逐个显示六节点的时令与旬空，体保持全盘根基；分别查看用、体互、用互、变用如何生克根体。不能只看本卦体用一条关系就忽略互变。若需统计同党数量，可以呈现数量事实，不自动把每个节点当相同权重的独立能量。

**空亡最终口径**：

- 六旬空支严格按仓库用户表。
- 起卦时旺、动或得扶，与静空、真空分开；“衰”不自动等于“衰极无气”。
- 真空需起卦时受日月侵害且衰极无气；未来填、冲、合也不能自动让它恢复。
- 假空/静空的后续应期优先填实，次选冲实。
- 合空默认关闭。明确启用且为婚姻/合作等需要合的事件，并满足动空或有依据的假空条件时，才列为限定候选。纯静空遇合不能自动出空。
- 起卦时的冲克与未来冲实保留各自时间语境。
- 经卦两地支仅部分命中，默认标部分命中，不清零整个卦。
- 模块输出地支节点；公历候选日期由历法模块产生，保留使用的是年/月/日/时尺度。没有时间尺度依据时不可只给一个看似精确的日期。

这些是用户指定扩展，不能谎称都出自上传的三卷。引用传统“虚假/不实/心里没底”时用象意语气，不当作对真实人物的事实认定。

## 七、AI 的角色

首版不需要模型就能完成仪式、排盘、查文与规则依据展示。之后若接入模型，建立独立 `InterpretationProvider`：只接收结构化盘、选定领域原文、相关规则章节，返回简短概述、阶段说明和引用 ID。

模型不可改卦名、动爻、体用、月令事实、空支、基础等级；不可生成没有对应来源的“古籍原文”。模型层失败时降级为本地资料，主流程不能崩溃。不要把整本书连同每次问题全部发到 API。

未确定的综合等级规则保留为规则接口；用户之后补充时通过规则数据、版本和对应测试接入。不要为补齐界面私造综合吉凶算法。

## 八、视觉与性能标准

- 竖屏手机为主，适配安全区、刘海和小屏；文字大小可读，石桌按钮有足够触摸面积。
- 整体为石、木、香火、金色微光的材质语言；沉静、庄重、克制。三清像要有体量和清楚的三尊关系。
- 镜头过渡平稳；有跳过、声音开关与减少动态效果。触摸反馈可以轻微震动，不能强制权限。
- 设置移动端 DPR 上限、阴影质量档、模型/纹理预算；烟和粒子限制数量。给低端设备与 WebGL 初始化失败提供可用的2D降级。
- 卦象是数据驱动的，64卦不得画64份独立硬编码模型；阴阳爻共用几何体与材质。
- 石刻文字应与模型深度关系清楚；注意 z-fighting。可以合理使用可访问的 HTML 标签层，但不要让文字在镜头变化时漂离卦象。
- 资源预加载有轻量进度，不让用户对着黑屏等待。返回再进不重复加载全部资源。
- 不使用未获许可的三清像、道观照片、音乐或声音。

## 九、实施顺序与每阶段交付

### 阶段 A：知识与界面骨架

建立移动竖屏 app、知识层适配、手动排盘联调页、64卦库与逐爻详情。接入现有所有文本。完成一个本卦/互卦/变卦的组件和真实爻位置映射。先确保点初爻不会跳到上爻。

### 阶段 B：道观完整仪式

把入口、三清像、跪拜、三炷香、磕头、镜头转石桌连成完整可播放路径，先使用可替换的自建低模。采用状态机，例如 `idle → entering → kneeling → incense → bowing → revealing → reading`；每次切换幂等，取消/跳过/后台恢复不会重复提交。

### 阶段 C：石刻与解释联动

三卦显现、体用标签、实际方向箭头、动爻发光，点卦/爻打开面板。接月令与旬空依据、领域原文和来源。独立显示基础等级与条件性走势。

### 阶段 D：正式起卦与记录

历法适配、时区边界、起卦冻结、历史保存/删除/导出、语言框架、声音与减少动态效果。验证切后台恢复和重复点击。

### 阶段 E：手机打包与质感

Capacitor iOS/Android 工程、运行说明、图标/启动屏占位、资源许可清单、性能档位和降级。没有 Mac/Xcode 时仍完成项目配置和清楚的本地操作说明，不声称已经签名上架。

每阶段交付具体代码、可运行命令、已验证内容和真实剩余事项。完成当前授权范围内能做的工作，不反复让用户批准常规工程选择。若外部账号、签名或付费凭据才是阻碍，先做完其他工作并明确指出所缺内容。

## 十、验收清单

1. 能进入道观并完整经历三香、跪拜/磕头、石桌显卦；跳过得同一盘。
2. 本互变名称、阴阳结构、等级均来自仓库；49初爻动得到革→姤→咸，姤显示中卦。
3. 384种单动爻都可映射正确位置；初爻在底，上爻在顶。点一爻显示对应本卦爻文与白话。
4. 动爻所在经卦为用，静经卦为体；箭头方向正确，互变不另起体用根基。
5. 石桌默认文字少，长解释点击展开；白话、象传、民间诗象可辨。
6. 月令与旬空缺输入时标待提供；无假造日期、综合分数或成功率。
7. 真空后遇填冲仍保留真空条件；默认不以合空出空，限定场景和证据才可启用。
8. 固定等级不随模型生成或月令变化而被覆盖。
9. 离线、模型失败、低性能/WebGL失败均有可用路径。
10. `npm run validate`、原有测试、新增必要的规则边界及交互集成测试、app build 通过；记录测试设备/视口和未验证范围。

现在请先检查仓库与现有命令，再按阶段连续实现。遇到已记录的古籍异文，不凭感觉全局替字；必要订正需要证据、修改记录、可重建数据和对应校验。
