## 写作标准

- 每篇作为一篇完整文章写定，明确成、不成、迟成、得失或当前难解的结果。不能统一拼成“目前／经过／结果／日期／行动”几段固定句式，也不能只替换卦名和五行冒充逐篇重写。
- 六个可见经卦全部进入判断，一个原体贯穿；生扶、制克体者、连续生扶、泄体、月令和空亡都按本盘事实处理。成文时围绕这些作用讲事情如何发展，避免逐项报表。
- 真实动爻和用卦的变化必须解释。爻辞中的人物、婚配、刑罚、风雨等，不直接移植成用户必遇的现实情节。
- 日期融入对应的事件。说明何时可能收款、归来、会面有得，或交易受阻、争执反复；行动建议与应事预测分别保留依据。凶期不扩大成全天万事皆凶，换个吉日也不保证改变全盘结果。
- 写得直接，少套话；不用“需要一起看”“有某某方向”“可以观察”代替结论，不写规则纠错式的自言自语。
- 基础等级保持用户表。原创解释、古籍原句和历史案例反馈分别记录，新用户未来不得复制古案反馈。

## 日期硬约束

1. 起卦时冻结手机当地完整日期 `castingDate`。按日展示可含当天，所有预测日期都必须 `>= castingDate`。按时辰展示则还须由历法层排除已过去的具体时段。
2. 对近期按日事项，先找本月剩余日期。先执行本盘适用性筛选，本月没有合格候选才查下月。下月也没有合格候选时保留空结果，不造日期、不偷偷扩展到更远月份。
3. 跨月重新按完整日期查干支。例如11月30日起卦取酉日，下一月可匹配12月1日；不把过去的“8号”直接换成“下月8号”。筛选时继续核对填冲、月令变化和事情远近。
4. 新盘正文显示“本月20号”“下月1号”。数据库保存完整ISO日期与应事、吉凶、规则、筛选依据。正文数字只接受验证过的日期输入，不保存一组固定日号供所有人套用。
5. 旧盘保持原来的起卦条件和日期，不随查看时间重新选一轮。跨月回看，日期标签改显示实际月份；跨年时补年份。
6. 日期匹配只是历法候选，不自动成为唯一应验日。月、年尺度和婚姻等门类仍遵守各自原文，不为了本月／下月的显示形式强行改成按日预测。

## 可调用接口

```js
import {findUpcomingCivilDayMatches,formatUpcomingCivilDay} from '../src/index.js';

const result=findUpcomingCivilDayMatches({
  castingDate:'2026-11-12',
  branches:['戌'],
  // 若需要填实等先决条件，在此用规则模块逐日返回true或false。
  isEligible:day=>day.date>='2026-11-12'
});
// 这里只会匹配本月20号，不会返回已经过去的8号。
// result.selectedCycle仍是null，不能宣称已经确定唯一应验轮次。

formatUpcomingCivilDay('2026-11-08',{castingDate:'2026-11-12'});
// RangeError：日期早于起卦日，禁止用于新盘正文。

formatUpcomingCivilDay('2026-11-20',{
  castingDate:'2026-11-12',viewDate:'2026-12-12'
});
// “11月20号”，原日期未改成12月20号。
```

`isEligible`是同步布尔筛选器，由完整规则层提供；省略时仅得到日历匹配。这里没有新增一个能自动替代月令、旬空、应事及轮次判断的总断器。完整3D应用还须在最终正文填入日期前调用这些接口并持久化结果。
