# 规则、依据和优先级

当前规则包 `user-classical-plus-void / 1.1.0`。这是本项目采用的明确口径，不宣称解决所有流派差异。

## 来源优先级

1. 用户最新明确订正：天风姤显示“中卦”；应期先填后冲，合空限定；真空不会被未来节点自动恢复；用、互、变依次与体卦比较，用卦影响最大（2026-11-11）。
2. 用户上传的吉凶表及空亡扩展。等级是固定资料，不按 AI 喜好改写。
3. 《梅花易数》原文中可复核的起卦、体用、互变、生克与旺衰规则。
4. 为使程序可运行而作的显式工程约定，例如部分地支命中的处理。它们不是古籍原文。

## 排盘与体用

先天数：乾1、兑2、离3、震4、巽5、坎6、艮7、坤8。阳1阴0，六爻自下而上。

单动爻落在哪个三爻经卦，那个为用；另一个为体。体代表自己/主，用代表事情/事。**本卦有动爻，不称静止的体卦另有动爻。**

变卦仅翻转本卦指定的一位。互卦的下卦由二三四构成，上卦由三四五构成。《互卦起例》还载“乾坤无互，互其变卦”，故提供可选策略，不在乾坤时静默切换算法。

主次映射：本卦=目前，用为即应；互卦=经过；变卦=结果。这个阶段展示是传统占断结构的 UI 呈现，不是已验证的未来事实。

| 关系 | 石桌短句 | 详情原则 |
| --- | --- | --- |
| 体克用 | 主制事 · 可掌控 | 还要核对体旺衰、领域、空亡 |
| 用克体 | 事克主 · 主不顺 | 克体之源若真空/静空，受害条件可能减弱 |
| 体生用 | 主生事 · 有耗费 | 泄体，核对生扶和领域例外 |
| 用生体 | 事生主 · 有助益 | 助力若空，收益可能难落实 |
| 比和 | 主事相和 | 仍需看旺衰，不直接推出事必成 |

全盘根体固定。体与用、体互、用互、变用分别比较；不要把互卦或变卦重新当成新起一盘再找一次动爻。相同经卦在不同阶段可有各自角色，但不把变卦沿用的体重复算一个生扶来源。展示相生相克事实和旺衰条件，暂不发明固定权重总分。

## 用 → 互 → 变 综合判断（用户规则 2026-11-11）

用户原话要点：本卦分体用看关系，互卦也分体用看关系；用卦、互卦、变卦三者分别与体卦比较，断定吉凶。用卦克体，事情开始就不顺；互卦克体，发展过程不顺；变卦克体，最终结局不尽人意；用、互、变生扶体卦，事情顺利如意。三者对体卦影响：**用卦最大，互卦其次，变卦最后**。很多时候只要用卦克体，事情就坎坷不顺。

古籍对应：《体用互变之诀》“卦用最紧，互次之，变卦又次之……体互最紧，用互次之……变卦克体，事于末后，必有不吉。变生体及比和，则事事临终有吉利”；《体用总诀》“用吉变凶者，先吉后凶；用凶变吉者，先凶后吉”；卷三《体用》“生体多者则愈吉，克体多者则愈凶”。

实现（`synthesizeReading`，`src/index.js`，结果字段 `reading.synthesis`）：

| 阶段 | 比较 | 白话 |
| --- | --- | --- |
| 开局（即应） | 用卦 ↔ 体卦 | 开局得助／顺和／可掌控／有耗费／受制 |
| 过程（中间之应） | 体互 ↔ 体卦（定调），用互 ↔ 体卦（并列显示） | 过程得助／……／受阻 |
| 结局（终应） | 变卦用侧 ↔ 体卦（变卦体侧即原体，不重复计） | 结局得助／……／不尽如意 |

- 生体、比和、体克用为“顺”；体生用为“耗”；克体为“不顺”。
- 总基调由用卦定：用克体 → “以不顺为主”，即使结局比和也不改基调，只写“末后渐顺”。
- 标题由开局与结局组合：先难后易、先易后难、始终顺遂、始终受制等九种。
- 附注：克体者多／生扶者多、体党／用党、体卦旺衰（仅当已提供月建）、逢空或减。
- 只有顺序，没有分数、权重或成功率。
- 证据分工（规则 v2）：用卦 → 当前，互卦（体互定调）→ 过程，变卦 → 后势。每段给出白话证据（如“当前不利，存在明显阻碍”“中间可能获得帮助”“后续存在改善条件”）。
- 综合结论由（用，变）组合给出一句话，`{outcome}` 由应用按所问之事填入（如“拿到这份工作”）。冲突组合须写明边界：用克体而变卦生扶比和 → “前期阻力较大，后续有缓和机会，但目前不足以断定一定能……”，并注明“结局比和或生体只说明末后有转机，不能单凭此断定事成”；用吉变凶 → “起初顺利，但后势受克……不宜过早定论”。不利组合附“什么情况下判断会改变”：体卦得令乘旺、克体之卦衰或逢空、另有生体之卦相助（《体用衰旺之诀》、卷三《体用》）。
- 同一组体用证据在任何领域给出同一结论类型（`verdict.code`），只换所问之事的说法。
- 天时占“不分体用”，改按《天时占第一》“全观诸卦”：数本、互、变六个经卦，取最多者之象（离多主晴、坎多主雨、坤乃阴晦、乾主晴明、震多则雷、巽多则风、艮多则久雨必晴、兑多则不雨亦阴）；坎离同多为“时晴时雨”。石桌刻“天时 · 震多 · 雷动”这类事实。
- 石桌刻字改为三段事实（如“用克体 · 互克体 · 变比和”），不再只刻本卦一句“主不顺”作整盘结论。
- 《体用互变之诀》中观梅恒卦的个案表述与起例不全相合（见 `data/issues.json` mh-117），只采用其通则，不以个案生成结构。

断语库接入后，断语原文仍由作者提供、按卦与领域整段返回；本综合只是体用生克的结构判断，不改写断语。

## 月令

卷一《卦气旺》《卦气衰》、卷二《体用总诀》、卷三《体用衰旺之诀》为依据：春木旺土衰，夏火旺金衰，秋金旺木衰，冬水旺火衰，辰戌丑未月土旺水衰。其余元素返回“原条目未明示”，不伪称原文已有完整旺相休囚死表。

历法输入单独记录：时间起卦的农历月数，与论旺衰使用的月建、节气边界，是两个不同字段。模块不根据电脑当前月份偷偷猜月令，也不把美国本地时区默认为北京时间。完整应用需实现并验证历法适配层，保留公历时间、IANA 时区、UTC 偏移、月支、日干支、子时换日和闰月政策。

## 真空、假空与节点的顺序

1. 固定起卦时的日干支与旺衰、生扶、刑冲克害证据。后续时间流逝不应改写当初证据。
2. 动不为空、旺不为空；得明确生扶列为假空/待落实。既“衰极无气”又“旺或得扶”的输入相互冲突，报错复核。
3. **真空须同时衰极、受日月侵害。真空即使未来填实、冲实、合空，也不自动恢复作用。** 程序维持 suppressed，显示已碰到何种节点供核对。
4. 非真空静空可以待填/待冲。填实优先，冲实次之；两支命中时逐支保存释放条件，不含糊地说已全部出空。
5. 合空默认关闭。只有显式启用，事项为婚姻/合作，且起卦状态属于动/旺/得扶假空时，才列限定牵合落实节点。纯静空仅遇合不能自动出空。
6. 起卦时“日月冲克导致真空”和将来“冲实”是不同时间层的条件，不互相覆盖。

“用逢空”的不实或隐瞒、“体逢空”的心里没底，作为传统象意提供，不能输出为对现实人物撒谎、心理状况的事实诊断。用户原话的“必成、必发”保留在来源含义中，产品结果表达为条件性传统解释。

## 固定等级与情境判读

基础等级来自用户表，最终五档分类：上上15、中上20、中中8、中下8、下下13，共64。44姤的显示文字为“中卦”，分类属于中档；除这一显示别名，其余按原表显示。等级不会因改月令或改空亡而悄悄改变。

18 个领域有不同断法，例如饮食领域的“体克用，则饮食有阻”，不能套统一“体克用事必吉”。天时明确“不分体用”。疾病、生产保留历史资料供查阅，不把古籍死亡/胎儿性别/药性推断变为软件事实结论。领域原文和综合解释必须可分辨。

## 规则实现1.1.0

明确月令五行生该卦，以及日干支基准下日支五行生/比扶该卦时，自动保存 `supportEvidence`，用于用户指定的有扶假空判断。没有生扶证据时不凭叙事补出助力；“衰极”和日月刑冲克害仍须明确证据，不由单一月衰直接推出。故事详见 [STORIES_AND_TIMING.md](STORIES_AND_TIMING.md)。
