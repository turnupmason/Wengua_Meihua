## 四、完整用户流程

### 1. 简洁入口

显示应用名“问卦 / Wengua”和“入观 / Enter”。入口可选择语言、声音开关与减少动态效果。用户问题和事项分类可在入观前轻量填写，也可留空。不强迫注册。

### 2. 入观

竖屏第一视角，从道观入口看见内部结构与远处三清像。通过短镜头推进或触摸引导到祖师像前；移动端不要求玩家操纵复杂的游戏摇杆。入口、殿堂、像与石桌要在空间里有明确关系。光线偏暖、低饱和，少量烟与空气尘埃；不做刺眼闪光、镜头抖动。

### 3. 入观与赐卦

（2026-11-10 用户订正：不再上香、跪拜、磕头。）在殿内选好问事领域与起卦方式后点“入观”，此时冻结起卦结果；镜头望着三清缓步上前，转到石桌坐下，随即祖师赐卦。问卦三戒在行进途中以字幕显示。镜头运动舒缓。

提供“跳过仪式/直接观卦”，以及减少动态效果模式。跳过与完整播放必须得到**同一份已经冻结的起卦结果**。音频需要首次手势后再启用；切后台后暂停动画和音频，恢复时不重复起卦。

### 4. 石桌显卦

镜头移到石桌，桌面有可读的空间与留白。按本、互、变顺序显现三组完整六爻，效果是刻痕与柔和金色微光，不是悬浮游戏卡牌。可先做能清楚表达刻痕的几何/材质方案，再逐步加法线、粗糙度和刻字细节。

三组下方始终只放少量信息：

```text
本卦 · 泽火革        互卦 · 天风姤        变卦 · 泽山咸
   上上卦                中卦                中上卦
     目前       →        经过        →        结果
```

示例来自本卦49初爻动；显示等级必须读取当前资料，不照抄演示文字到所有卦上。

**等级最新要求**：44天风姤最终显示“中卦”，之前改上上卦的要求已被用户覆盖。其他卦保持原表。五档分类按 `canonicalGrade`，前台文字用 `rawGrade`。不要自加“上卦”第六档，不把“中卦”又自动改回上上或中上。

### 5. 体用与生克箭头

在本卦对应的上下三爻旁，直接标明：

- `体：自己 · 主`
- `用：事情 · 事`

可以补一个经卦名和五行，如“体 兑金”，但不要同时堆出整套规则解释。箭头必须与真实的生/克方向一致，并配一个关系名与一句短语：

| 关系 | 主界面短语 |
| --- | --- |
| 体克用 | 主制事 · 可掌控 |
| 用克体 | 事克主 · 主不顺 |
| 体生用 | 主生事 · 有耗费 |
| 用生体 | 事生主 · 有助益 |
| 比和 | 主事相和 |

比和使用双向或无方向连接，不能画成单向克。当前 `edges` 保留真实 from/to。箭头既有文字也有形状区分，不只靠红绿颜色。

这句是结构关系提示；领域与月令可能改变实际解释。例如饮食占中“体克用”有“饮食有阻”的专门语义，不能因此仍宣告“本次必吉”。详情优先引用该领域条文。

### 6. 精确的动爻发光

最重要的数据交互：**本卦的哪一爻动，就让那个位置发光，并显示那个位置对应的原文、白话和小象。**

初爻在最底部，上爻在最顶部。对3D模型应保留 `hexagramId, stage, linePosition`，射线命中后以这些字段查询。阴爻有左右两段，但属于同一条爻，触摸任一半段查同一个记录。

动爻所在的三爻经卦为用，另一个静止经卦为体。用户口头提到“体卦的动爻”时，此处按本卦动爻实现，不改变经典体用定义。

默认只有本卦的本次动爻用持续金色微光标记。互卦没有新的独立动爻。变卦可以用另一种低强度标记提示“对应变化位置”，不能伪装成第二次发动。详情浏览其他爻使用“选中态”，与本次动爻视觉区别明确。乾用九、坤用六放特殊条目，不画第七条爻。

在64卦详情库里，用户可以逐爻点击；从本次占卦进入时自动选中本卦真实动爻，不因打开面板改掉起卦结果。

### 7. 点击才展开解释

点卦名/整组卦象打开底部详情面板，点某一爻直接定位到它。详情至少包含：

1. 卦名、用户等级、当前阶段、上下经卦。
2. 卦辞与对应白话。
3. 大象与白话，和用户提供的吉凶诗象明确分开。
4. 当前爻的爻辞、白话、小象与白话。
5. 体用、生克、月令、旬空的本次依据。
6. 适用领域的古籍原文、相关章节与来源入口。

长内容允许收起“古文/白话/断法依据”，阅读时不遮断关闭和返回操作。主桌面不承载这些长段落。

### 8. 保存与重看

起卦时冻结结果并生成 cast ID，保存问题、领域、起卦法、原始数值、完整时间/时区、历法换算结果、规则版本、动爻、三卦 ID 与显示等级快照。文字详情可按 contentVersion 重现；用户规则更新后旧记录应仍能解释当时采用了哪一版，不能后台偷偷换结果。

用户问题和历史默认只在本地。支持删除和导出；不把问题自动发给模型或埋点服务。

## 五、起卦与历法接入

首先提供可靠的手动联调模式：选本卦与动爻，直接验证三卦与资料。正式流程默认采用卷一《年月日时起例》，可增加明确命名的报数方式。不同方法保留不同输入与规则，不能把不明算法都称为古法。

时间法已提供 `castByTimeParts`。调用方需提供年支序数、农历月日、时支序数；不要把公历年月日直接送进公式。美国用户必须记录 IANA 时区，覆盖夏令时开始、结束和本地跨日。

请建立 `CalendarProvider`：输入带时区的明确时刻，输出农历月日、年支、月建、日干支、时支和边界政策。选定可验证的历法实现，记录版本与来源并核对样例。农历起卦月与论旺衰的月建分开。换年、节气月建、闰月和子时换日政策显式存储，不因设备时区变化重算已保存记录。

没有足够依据的历法边界先保留为可配置政策，同时把可靠的手动输入与仪式流程做完整；不能用 `new Date()` 的当前公历月替代月令后宣称已完成。

## 六、月令、全盘生克与空亡

基础等级只来自表。当前三卦在特定事情中的走势，使用领域断法、体用、互变、旺衰与用户空亡规则另行解释。不要先拍一个0–100的能量分数，再反过来写成古籍定论。

逐个显示六节点的时令与旬空，体保持全盘根基；分别查看用、体互、用互、变用如何生克根体。不能只看本卦体用一条关系就忽略互变。若需统计同党数量，可以呈现数量事实，不自动把每个节点当相同权重的独立能量。

**空亡最终口径**：

- 六旬空支严格按仓库用户表。
- 起卦时旺、动或得扶，与静空、真空分开；“衰”不自动等于“衰极无气”。
- 真空需起卦时受日月侵害且衰极无气；未来填、冲、合也不能自动让它恢复。
- 假空/静空的后续应期优先填实，次选冲实。
- 合空默认关闭。明确启用且为婚姻/合作等需要合的事件，并满足动空或有依据的假空条件时，才列为限定候选。纯静空遇合不能自动出空。
- 起卦时的冲克与未来冲实保留各自时间语境。
- 经卦两地支仅部分命中，默认标部分命中，不清零整个卦。
- 模块输出地支节点；公历候选日期由历法模块产生，保留使用的是年/月/日/时尺度。没有时间尺度依据时不可只给一个看似精确的日期。

这些是用户指定扩展，不能谎称都出自上传的三卷。引用传统“虚假/不实/心里没底”时用象意语气，不当作对真实人物的事实认定。

## 七、AI 的角色

首版不需要模型就能完成仪式、排盘、查文与规则依据展示。之后若接入模型，建立独立 `InterpretationProvider`：只接收结构化盘、选定领域原文、相关规则章节，返回简短概述、阶段说明和引用 ID。

模型不可改卦名、动爻、体用、月令事实、空支、基础等级；不可生成没有对应来源的“古籍原文”。模型层失败时降级为本地资料，主流程不能崩溃。不要把整本书连同每次问题全部发到 API。

未确定的综合等级规则保留为规则接口；用户之后补充时通过规则数据、版本和对应测试接入。不要为补齐界面私造综合吉凶算法。

## 八、视觉与性能标准

- 竖屏手机为主，适配安全区、刘海和小屏；文字大小可读，石桌按钮有足够触摸面积。
- 整体为石、木、香火、金色微光的材质语言；沉静、庄重、克制。三清像要有体量和清楚的三尊关系。
- 镜头过渡平稳；有跳过、声音开关与减少动态效果。触摸反馈可以轻微震动，不能强制权限。
- 设置移动端 DPR 上限、阴影质量档、模型/纹理预算；烟和粒子限制数量。给低端设备与 WebGL 初始化失败提供可用的2D降级。
- 卦象是数据驱动的，64卦不得画64份独立硬编码模型；阴阳爻共用几何体与材质。
- 石刻文字应与模型深度关系清楚；注意 z-fighting。可以合理使用可访问的 HTML 标签层，但不要让文字在镜头变化时漂离卦象。
- 资源预加载有轻量进度，不让用户对着黑屏等待。返回再进不重复加载全部资源。
- 不使用未获许可的三清像、道观照片、音乐或声音。
