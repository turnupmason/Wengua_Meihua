## 有多少组合

采用现有单动爻、标准互卦法：本卦64 × 动爻6 = 384盘。互卦由二三四、三四五爻取出，变卦只翻转指定爻；两者随本卦与动爻确定。不是三个互不约束的64卦相乘。此法实际出现16种互卦。

月令按已上传原典明确的五类气令组织：春木、夏火、秋金、冬水、季月土。**384 × 5 = 1,920篇完整三阶段基础故事**。这里不以12个月支名称作故事索引。月支可以由历法适配为月令；应期采用的地支另有用途，二者不是同一个字段。

每个节点另保存月令五行与该卦的生克关系；月令生该卦、明确日建生或比扶该卦时，保存可核对的生扶依据，按用户的假空规则处理。不会把“可能有人帮忙”当作这种证据。

旺衰严格沿用《卦气旺》《卦气衰》《体用衰旺之诀》。未在这些条文中明示的其他五行保留 `not_explicit`，不为了写顺故事就擅自补成“旺相休囚死”全表。

## 如何讲成一个故事

每篇含目前、经过、结果三段：

- 本卦描绘眼前处境，结合本体与用的关系、月令说明目前如何着力。
- 互卦铺陈中段，分别看体互、用互对原体的作用，不能只取有利的一面。
- 变卦收束末段，仍以原体为基准，写承接、压力或消耗的方向。

64卦的象意画面在 `data/story-portraits.json`。各状态采用的文句在 `src/narrative-rules.js`，全量故事在 `data/stories/01.json` 至 `64.json`。18领域的原文依据与专门文句在 `domain-rules.json`，空亡句在 `void-rules.json`。

运行时按事情与空亡状态选择已写文句，连成最终故事；不需要请求语言模型。古籍原文、原创解释与古籍反馈都有各自来源标识。

## 按事情处理空亡

求财区分预期、账面与实际到账；交易与合作核实承诺、交付及履行；婚姻核实双方回应与约定；失物区分模糊线索与真正寻回；其他领域也有各自核对重点。

代码逐一检查原体、用、体互、用互、变用。克体的静卦判真空时，说明该项克力减弱，不直接推成事情必成；生体来源空时，说明助益的落实需要观察。动空、旺空保持作用，部分命中不清零整个经卦。真空先按起卦时证据判断，后来填冲不自动恢复。

天时原文要求“不分体用”，采用合看三卦与时令的专门叙述。生产、疾病保留为传统文献参照，不把生克输出成现实诊断、生死、疗效或用药结论。

## 应期怎样写

`buildTimingPlan` 返回候选与理由，原典依据主要是《占卜克应之诀》（mh-122）、八卦时序（mh-052）、十二地支（mh-012），以及用户的空亡时间规则。

1. 生体、比和的卦气可作助益候选；克体的卦气作留意阻力的候选。采用卦气五行所属支，不混用后天方位经卦地支的旬空映射。
2. 逢空而允许等待落实时，填实优先，冲实次之。真空不列为后遇填冲即可落实；部分未定和已经释放的状态不重复下“等待填实”结论。
3. 合空默认关闭，只有显式启用、婚姻/合作事件、且动或得令/生扶假空满足时，才列为限定候选。
4. 时间尺度要按事情远近给定。提供 `timingScale='day'` 和日干支，能计算未来下一次相关支日在起卦后第几日；没有尺度时列支候选，不虚构某个公历日期。
5. 跨日、夏令时、公历年月日须由应用的历法适配层转换。这里不会把服务器UTC日或北京日偷偷套到美国用户身上。

后天取象数与动静数应另行提供 `castContext`。目前只明确支持物卦数+方卦数+时支数且能够复现原盘的路径：行取半、立取原数、坐取倍，需显式选择近日按日。分数结果保留待解释，不自动四舍五入。时间起卦、其他报数法不自动套这条取半/取倍法。

## 可直接调用

```js
import {loadLibrary, createNarrativeRepository} from './src/index.js';
const library = await loadLibrary();
const stories = createNarrativeRepository({library});
const result = await stories.getStory({
  primaryId: 49,
  movingLine: 1,
  monthOrder: 'spring-wood',
  domainId: 'domain-10',
  voidContext: {ganzhi: '甲子'},
  timingScale: 'day'
});
console.log(result.story);       // 连贯的目前、经过、结果、空亡与应期
console.log(result.timing);      // 每个候选的来源、条件、相对日数
console.log(result.reading);     // 可核对的结构盘
```

此例时令与干支是联调输入，不代表今天。`getBase` 读取1,920篇中的基础故事；`getClassicalCases({primaryId,movingLine})` 查已拆解的对应案例。原生端可注入 `readJSON` 读取打包资源。

本版预写库明确采用 `inner-lines`。请求乾坤先取变卦之互等另一套策略时会报错，不用错误的预写故事迁就另一盘。

## 古籍案例的准确边界

`data/classical-cases.json` 首批拆出卷一10个明列案例、11张子盘，全部复算通过。原来的三卷全文仍完整保留；没有把方法论段落或后卷所有散例都宣称已经拆解。

- 观梅一节有预测，给定本节没有另叙后验，因此 `feedback=null`；不能添写成次日确有女子受伤。
- 同为姤四爻动，邻夜借物案与老人忧色案的情境、原数、动静及应期不同。匹配盘形不意味着可以照搬故事结果。
- 牛哀鸣预测“二十一日内”，反馈“后二十日”；数据分别记录21与20。
- 少年喜色的贲卦互为上震下坎，对离体有生也有克。书中“互变俱生”须限定所指，不能改写为全盘没有克体。
- 寺额案例含添笔前后两盘，且重视寺院外应；保留它的字画数假设，不拿现代笔画统计冒充原书。

每案均保存原文、原断、书中反馈、应期原数/尺度、复算盘与审校注记。反馈标为“书中记载”，不是本项目独立证实的现实事件。新盘输出 `reportedOutcome=null`，绝不插入这些历史反馈作为用户未来的结尾。
