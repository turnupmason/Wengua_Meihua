# 直接断语与动爻叙事 · 组合版本1.1.0

用户否定了只描述趋势、反复要求读者“结合实际观察”的旧文风。最终阅读必须给总断，写明动爻怎么改变事情，并给应期或明确的不取日期理由。

## 产品只显示最终解读

调用 `getStory`，显示 `verdict.summary`、`story` 或 `paragraphs`。新增字段：

- `verdict`：具体结果、总断口径、依据原句和四项全盘生克记录。
- `movingLine`：本卦真实动爻的位置、原文、解释、用卦变前变后、关系变前变后。
- `timingDecision`：本次实际采用的应期，最多两个首选节点；冲实次选保留在 `secondary`。
- `compositionVersion: '1.1.0'`：最终组合口径。基础资料仍是原经文版本，基础库版本仍为1.0.0。

`getBase`、`baseStory` 和 SQLite `monthly_narratives.paragraphs_json` 是旧版内部基础材料，**不能当作最终故事直接展示或直接回退展示**。这次重写的是所有 `getStory` 输出的组合层，未声称逐篇人工重写了1,920份基础文本。SQLite 使用者应按盘形和月令调用同一组合层；不得把旧文字当新版断语。

## 总断口径

`src/story-language.js` 中的 `direct-verdict-v1` 是公开可核对的编者合成口径，不冒充用户提供过完整决策表，也不冒充逐字古籍原文：

1. 变用对原体的关系作为末段结果，引用《体用总诀》《体用互变之诀》及对应门类条文。各领域分别翻译，不能将饮食体克用译成吉利。
2. 体卦真空优先覆盖一般有利结果，本次断不能承接；未来填冲不能自动恢复。
3. 末段生扶或配合静空，断眼下不能落实；末段凶力真空或静空，只断损害减轻，不据此凭空改成成功。
4. 体卦假空或静空，末段有利时在总断写明等体卦填实。旺空、动空保留作用，不统一套“等出空”。
5. 生体之卦失令，明确写所得不多；体弱而末段有利，明确写进展慢。这是定性编排，不生成金额、比例、成功率或额外综合等级。
6. 体互、用互分别进入中段，所有四条关系、各自月令和空亡均记录在 `verdict.relationEvidence`。中途有克不能隐去；互卦空也不能自动否定整个最终结果。

动爻必须写入故事。10个试读盘的短释有单独编写，其余采用用户提供且已绑定原卦原爻的白话。原文与来源完整保留。每盘还说明动爻使哪个经卦变成哪个经卦、生克关系如何变化；不把爻辞中的贵人、婚配、刑罚等字面情节直接虚构成用户已经发生的现实。

爻辞解释本次变化及行事得失，未设置“遇到吉字加分、遇到凶字扣分”的算法。固定等级保持用户表；总断不是改写固定等级。

## 应期取用

`timing` 仍保存完整条件与来源，供依据面板使用，旧 `timing.text` 不用于新版故事正文。新版显示 `timingDecision.text`：

- 体卦真空不报成事日；难成或耗损不硬塞一个成功日。
- 体卦、变用确需待空时，先取填实、后备冲实。中途一份助力静空，不自动变成整个结果必须等待的日期。
- 有可复现的原数、明确动静与日尺度时，采用相应数应；不拿古案天数移植给同形新盘。
- 其余采用末段生体、比和或克体卦气，优先显示本轮较近的两个节点。其他节点仍可在完整 `timing` 中查看，不宣称只有这两天能应。
- 日干支与日尺度明确才计算相对日数。缺尺度或缺依据直接说明缺什么，不编公历日期。

应期与总断属于传统预测表达，`reportedOutcome` 恒为null；真实事后反馈只能由用户另行记录。医疗门类不生成诊断、安危、疗效及用药结果；天时没有完整专用决策表时不把人事生克套成天气预报。

## 文风

像一个人把话说清楚：先难在哪里，哪一爻使事情起变化，中途怎么变，最后成不成、得还是失、迟还是快。禁止用“可以观察”“需要结合”“需要一起看”“有某某方向”“提供承接条件”等话代替判断。不写草木舒展、画面明亮等与结论无关的铺垫。

原典引用、预测断语、历史反馈分开保存。说话直接不等于宣称现实百分之百应验，也不等于能编出金额、具体人物、未经计算的日期。

## 验证

`npm test` 穷举384盘×5月令×15普通门类共28,800份最终输出，检查总断、真实动爻、四项生克、所选应期来自原计划、固定等级不变及旧套话不再出现在正文。另测真空覆盖、弱生扶、动空旺空不强等填实；保留原有古籍案例和数据库绑定测试。

`node scripts/build-story-previews.mjs` 可重建十篇试读。测试证明实现和绑定符合口径，不将传统预测证明为现实事实。
